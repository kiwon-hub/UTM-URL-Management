# UTM URL 관리 페이지

기원엠알오(kiwonmro.com) / 기원툴스(kiwontools.com)에서 쓰던 UTM 대장(엑셀)을 대체하기 위한
정적 웹페이지입니다. 빌드나 서버 없이 `index.html`을 열면 바로 동작합니다.

## 사용 방법

로컬에서 열어보려면 정적 파일 서버로 실행하세요 (파일을 브라우저로 바로 열면 일부 브라우저에서
로컬 스토리지가 제한될 수 있습니다).

```bash
python3 -m http.server 8080
# http://localhost:8080 접속
```

GitHub Pages 등 정적 호스팅에 그대로 올려도 동작합니다.

## 설계 원칙 (요청 사항 반영)

1. **전체보기 없음** — 기존 대장을 한 화면에 다 펼쳐두면 실수로 엉뚱한 URL을 복사하기 쉬워서,
   `사이트 → 채널 → 프로젝트 → 랜딩 페이지` 순서로만 골라 URL을 만들도록 마법사(wizard) 형태로
   제한했습니다. 직접 만든 URL만 "내가 만든 URL 기록"에 남습니다(브라우저 로컬 저장).
2. **utm_source / utm_medium은 채널 선택 시 기존 값으로 고정**되고 읽기 전용으로 표시됩니다.
   `utm_campaign`만 프로젝트(기본/무료샘플신청/심토스 전시회 등)에 따라 바뀝니다.
   목록에 없는 새 프로젝트는 "+ 새 프로젝트" 옵션으로 추가할 수 있는데, 이때도 반드시 기존
   설정 중 하나를 골라 source/medium을 유지하고 campaign 값만 새로 입력하게 되어 있습니다.
3. **메타(페이스북/인스타그램) 광고**는 utm_source/medium만으로는 두 매체를 구분할 수 없어서,
   "가이드" 탭에 Meta 동적 URL 매개변수(`{{site_source_name}}`, `{{placement}}` 등)를 이용한
   구분 방법을 정리해 두었고, "URL 생성" 탭에서 채널을 메타 광고로 선택하면 바로 적용할 수
   있습니다.

## 대리점 계약문의 (신청페이지 + 관리페이지)

무료샘플신청(`freesample`)과 같은 방식으로 **대리점 계약문의(`dealer`)** 프로모션을 채널별로
`data.js`에 추가했고, 신청/관리 페이지를 함께 만들었습니다.

### 전환 이벤트 — 접속과 제출을 각각

| 구분 | 이벤트 이름 | 발생 시점 |
| --- | --- | --- |
| 접속 전환 | `dealer_inquiry_view` | 신청페이지 진입 시 1회 (같은 세션에서는 중복 발송하지 않음) |
| 제출 전환 | `dealer_inquiry_submit` | 신청서 전송이 끝난 시점에 1회 |

두 이벤트는 GTM `dataLayer`, GA4 `gtag`, 메타 픽셀, 카카오 픽셀, 네이버 공통 스크립트로 동시에
발송되며 `utm_source / utm_medium / utm_campaign / utm_content / utm_term`이 파라미터로 함께
실려 나갑니다. 페이지에 해당 태그가 없으면 그 채널은 조용히 건너뜁니다.
GA4에서는 두 이벤트를 각각 **주요 이벤트(전환)** 로 등록해야 캠페인별 성과에 잡힙니다.

### 현재 페이지(구글폼 iframe)의 한계

운영 중인 주소는 `https://www.kiwontools.com/board/urgency/urgency2.html`이고, 지금은 구글폼을
`iframe`으로 띄우고 있습니다. iframe 안은 도메인이 달라서(docs.google.com) **부모 페이지에서 제출
여부를 알 수 없습니다.** 즉 지금 구조로는 접속 전환만 측정되고 제출 전환은 원천적으로 불가능합니다.
그래서 두 가지 적용안을 준비했습니다.

| 적용안 | 파일 | 응답 저장 | 접속 전환 | 제출 전환 |
| --- | --- | --- | --- | --- |
| A (권장) | `cafe24/urgency2.html` | 기존 구글폼/스프레드시트 그대로 | 정확 | 정확 |
| B (최소 변경) | `cafe24/urgency2-iframe.html` | 기존 구글폼 그대로 | 정확 | 추정(부정확할 수 있음) |

**A안** — 구글폼 iframe을 걷어내고 폼을 페이지에 직접 그린 뒤, 답변만 구글폼
`formResponse` 주소로 전송합니다. 응답은 지금 쓰시던 구글폼/시트에 똑같이 쌓이고,
제출 시점을 페이지가 직접 알기 때문에 제출 전환이 정확히 잡힙니다.
붙이기 전에 `GFORM.entries`의 `entry.숫자`만 채우면 됩니다
(구글폼 편집화면 → ⋮ → "미리 채워진 링크 만들기" → 만들어진 주소에서 `entry.숫자` 복사).
구글폼에 "유입경로(UTM)" 단답형 문항을 하나 더 만들어 `entries.utm`에 넣으면,
어떤 광고로 들어와 신청했는지가 시트에 함께 기록됩니다.
번호를 채우기 전에는 페이지 상단에 빨간 안내가 뜨고 전송이 막히므로, 설정을 빠뜨린 채
운영에 올라가는 일은 없습니다.

**B안** — 구글폼 iframe을 그대로 두고 "iframe이 두 번째로 로드되면 제출"로 추정합니다.
폼이 여러 섹션이면 페이지를 넘길 때도 로드가 발생해 과다 집계될 수 있어, 정확한 제출
전환이 필요하면 A안을 쓰세요.

두 파일 모두 카페24 게시판 HTML에 그대로 붙여넣는 형태(맨 위 `<!--@layout(...)-->` 포함)이고,
스타일·스크립트가 파일 안에 모두 들어 있어 외부 파일을 올릴 필요가 없습니다. 한글이 깨진다면
쇼핑몰 스킨과 같은 인코딩으로 저장했는지 확인하세요(카페24 관리자 HTML 편집기에 붙여넣으면
자동으로 맞춰집니다).

### 자체 호스팅 버전 (`dealerform.html` + `dealer-admin.html`)

구글폼 없이 이 저장소만으로 운영하고 싶을 때 쓰는 버전이고, A안 페이지의 미리보기이기도 합니다.

| 구분 | 파일 | 용도 |
| --- | --- | --- |
| 입력 페이지 | `dealerform.html` | 대리점 계약문의 신청서. 유입 `utm_*`을 함께 저장 |
| 관리 페이지 | `dealer-admin.html` | 접수 목록 · 상태/메모 관리 · 캠페인별 접속·제출 집계 · CSV 내보내기 |

전환 이벤트 이름과 광고 계정별 전환 ID·라벨, 문의 저장 위치는 `dealer-common.js` 상단의
`CONFIG` 한 곳에서 설정합니다.

```js
const CONFIG = {
  endpoint: "",                                   // 문의를 받을 API 주소 (비우면 브라우저에만 저장)
  events: { view: "dealer_inquiry_view", submit: "dealer_inquiry_submit" },
  googleAds: { view: "", submit: "" },            // 예: "AW-123456789/AbCdEfGhIj"
  naver: { viewType: "", submitType: "2", submitValue: "0" },
  kakao: { trackId: "" },
  meta: { view: "DealerInquiryView", submit: "Lead" }
};
```

`CONFIG.endpoint`가 비어 있으면 문의와 이벤트 로그가 **그 브라우저의 localStorage**에만 쌓입니다
(단독 테스트용). 여러 담당자가 같은 접수 목록을 보려면 JSON을 받는 주소(Google Apps Script 웹앱,
자체 API 등)를 넣으면 되고, 신청 시 `POST` · 관리페이지 조회 시 `GET`을 사용합니다.
서버 전송이 실패하면 문의를 잃지 않도록 로컬에 백업합니다.
A안(구글폼 전송)으로 운영할 때 접수 목록은 기존 구글폼 응답 시트에서 보시면 됩니다.

## 파일 구성

- `index.html` — 페이지 구조 (URL 생성 탭 + 가이드 탭)
- `styles.css` — 스타일 (UTM 도구 + 대리점 계약문의 페이지 공통)
- `data.js` — 기존 UTM 대장(엑셀)에서 추출한 사이트/채널/프로젝트/랜딩페이지 데이터
- `app.js` — 단계별 선택 로직과 URL 생성/기록 로직
- `dealerform.html` / `dealer-form.js` — 대리점 계약문의 입력페이지 (자체 호스팅 버전)
- `dealer-admin.html` / `dealer-admin.js` — 대리점 계약문의 관리페이지
- `dealer-common.js` — 두 페이지가 공유하는 UTM 수집 · 전환 이벤트 발송 · 저장 로직
- `cafe24/urgency2.html` — 카페24 게시판용 A안 (자체 폼 → 기존 구글폼으로 전송)
- `cafe24/urgency2-iframe.html` — 카페24 게시판용 B안 (구글폼 iframe 유지, 제출은 추정)

## 데이터 갱신

새 채널이나 프로젝트가 생기면 `data.js`의 해당 사이트 `channels` 배열에 항목을 추가하면
됩니다. `medium`은 채널 전체에 고정값을 둘 수도 있고, variant(프로젝트)마다 다르게 둘 수도
있습니다(예: 리마케팅 여부에 따라 medium이 달라지는 경우).
