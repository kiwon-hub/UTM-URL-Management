## 4. 실제 입력 패턴

### 4-1. 업체명에 주문경로가 괄호로 붙음 (MRO잡자재·MRO)
- `김OO(네이버페이)`, `김OO(쿠팡)`, `제이엠인더스트리(자사몰)`, `주식회사네오테크(무통장입금)`
- 순서가 뒤바뀐 경우도 있음: `아이마켓(진양오일씰)` 87행 vs `진양오일씰(아이마켓)` 23행 → 같은 거래처로 묶어야 함.
- MRO잡자재 업체명 고유값 712개 중 상당수는 온라인 개인 구매자 → 거래처 구분 `ONLINE_PERSON` 으로 분리 제안.
- 표기 변형: `MRO 재고`(39) / `MRO재고`(37), `기원재고` / `기원 재고` / `성도 재고` / `성도재고`.
- 한 칸에 여러 업체: `전진공구 + MRO 재고`, `툴탑,MRO재고`, `강/STOCK,JAEKYONG` → 원문 보존 + 대표 거래처 1개 지정.

### 4-2. 담당자 표기
| 시트 | 값 (건수) |
|---|---|
| 베트남 | 이슬 311, 민구 140, 소라 20, 종현 18, **신종현과장님 16** (101행 공란) |
| MRO | 민구 158, 소라 2, + 잘못 들어간 값 `와이지원제품으로`, `티에스` |
| 기원툴스 | 민구 67, TS 3, `재고보유` 2, 신종현과장님 1, **숫자 19건 (단가가 담당자 열에 들어감)** |
| 기원재고 | 민구 114 |
| MRO잡자재 | 거의 공란 (이슬 3) — 숫자 3건, `2포대 4/6` 1건 |

→ 사용자 테이블에 `aliases` (예: 종현 ← 신종현과장님) 를 두고 매칭, 매칭 안 되는 값은 오류가 아닌 **경고 + 원문 보존**.
→ 담당자 칸이 대부분 비어 있는 시트(MRO잡자재 99%, 기원툴스 92%)는 **시트별 기본 담당자**를 업로드 화면에서 지정하는 방식 제안.

### 4-3. '일정 / 진행상황' 열에 여러 정보가 섞임
- **제작·매입처 이름**: 베트남 `경성기공` 39, `탑다이아` 22, `동신툴피아` 19, `동현콜렛트` 19, `에스엠테크` 14 … / 기원툴스 `대승정밀`, `알엔와이-12000 / 납기 2주`
- **재고 상태**: `재고 보유`/`재고보유` 45, `재고없음` 20+14, `현 재고 0`, `현재고 X`
- **일정 요청**: `하루일정으로 만들어주세요`, `하루 일정으로 부탁드립니다` (띄어쓰기 변형 다수)
- **진행 상태**: `준비완료`, `발주취소`, `미납 10개`
- **매입 단가**: `툴프로 5,500`, `알엔와이-14000`, 숫자만 (23000, 176000)

→ 원문은 `memo` 에 그대로 두고, 상태·제작처는 **추천값**으로만 보여 주고 사용자가 확정.

### 4-4. 단위 표기 변형
- MRO잡자재 27종: `봉` 440, `포대` 419, `PK` 281 + `pk` 62, `BOX` 214 + `box` 23 + `박스` 9, `EA`, `통`, `켤레`, `매`, `곽` …
- MRO: `EA` 295, `Ea` 2, `개` 1 / 기원툴스: `EA` 1,189, `Ea`, `ea`, `장` 5

### 4-6. 부분납품 기록 방식 (가장 중요)
엑셀에는 납품 이력 칸이 없어서 자유 텍스트로 적습니다.

| 위치 | 예 | 건수 |
|---|---|---|
| 비고 | `1/19 30개발송 / 1/23 48개 발송`, `72개중 2/11 30개 발송`, `7/7 10개 출고` | 베트남 120행, 기원툴스 9, MRO 5, MRO잡자재 4 |
| 셀 메모(comment) | 베트남 수량 열 60건: `6/25 출고후 기준 미납 73개 7/14 미납 수량 마감처리` | 베트남 60 |
| '미납' 언급 | `미납 10개`, `1개 미납있음`, `코팅제품 미납 5개` | MRO 19, 기원툴스 14 |
| 발송날짜 칸 | `10개 2/26`, `8개로 마감`, `6/11 127개 출고` | 소수 |
| 엔티와이반도체 하단 집계표 (13~18행) | 품목코드·규격·총 발주 수량·총 미납 수량·기원 본사 대기 수량·`1/16 발주`·`2/12 출고`·`3/3 출고`…`6/1 출고`·`4/6 발주` 열 | 5개 품목 |

- 엔티와이 집계표는 **날짜별 출고 수량이 열 머리글**에 있는 구조이며, `총 미납 = 총 발주 - 각 출고 합` 수식이 있습니다. 이것이 바로 시스템의 `deliveries` 테이블 구조와 같습니다.
- `미납 수량 마감처리`, `8개로 마감` → 남은 수량을 더 보내지 않고 종결하는 업무가 실제로 있음 → `cancelledQty` (마감수량) 필드로 반영.
- 텍스트 속 `M/D N개` 패턴은 업로드 때 **납품이력 후보**로 추출해 보여주고, 사용자가 체크한 것만 이력으로 저장하는 방식 제안.

### 4-7. 반품
- 기원툴스 318행: 같은 품목(KW109353)을 **수량 -40** 으로 한 줄 더 입력. 바로 위 행 메모 `6/15 40개만 반품예정`.
- → 음수 수량 행은 발주로 만들지 않고 원본만 보존(업로드 화면에서 '오류'로 분리). 담당자가 원래 품목(317행)의 납품이력에 `RETURN` 40개로 등록합니다. 자동 연결은 [제안]으로 2차에 검토.

### 4-8. 한 발주를 구분하는 단서
- 발주번호 칸이 **없습니다.** 한 거래처가 같은 날 여러 품목을 주문하면 연속된 행으로 적습니다.
- '날짜 + 업체' 가 연속으로 같은 묶음 수: 기원툴스 457, MRO잡자재 1,196, 베트남 380, MRO 222, 기원재고 72
- MRO잡자재(245행)·MRO(115행)는 **빈 행으로 묶음을 구분**하는 습관이 보입니다.
- → 묶음은 '추천'일 뿐이므로 **자동으로 합치지 않습니다.** 기본은 "원본 1행 = 품목 1개", 묶기 추천을 사용자가 승인했을 때만 한 발주로 묶고, 묶었다는 사실(`groupingMethod`)과 원본 행번호를 남깁니다.

## 7. 이관 시 주의사항

1. **원본 보존이 1순위**: 모든 원본 행을 `legacy_rows` 에 (파일 해시, 시트명, 행번호, 셀 원문, 서식 플래그) 그대로 저장한 다음 변환합니다. 변환 규칙이 틀려도 다시 돌릴 수 있습니다.
2. **자동 병합 금지**: 날짜+업체 연속 묶음은 추천만.
3. **상태 추정은 옵션**: 노란색/취소선/발송날짜 → 상태 변환은 업로드 화면에서 규칙별로 켜고 끔.
4. **텍스트 속 부분납품은 후보**: `1/19 30개 발송` 같은 패턴은 후보로 보여주고 확인 후 저장. 연도가 없으므로 발주일 연도(2026)로 보정.
5. **중복 업로드 방지**: 파일 해시 + (시트, 행번호, 날짜, 업체, 품명, 수량) 지문으로 재업로드 탐지.
6. **테스트 DB에서 먼저**: 최초 이관은 테스트 DB에서 리허설 → 결과 확인 → 운영 DB 반영.
7. 원본 파일에 개인 구매자 이름·연락처가 있으므로 저장소·메신저 공유 금지, 서버 보관 파일은 접근 권한 제한.
