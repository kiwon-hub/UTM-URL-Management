# 2단계: 업무 흐름 및 화면 구성 제안

> **[확정]** = 요청서에 명시된 내용, **[엑셀]** = 엑셀에서 확인된 실제 업무, **[제안]** = 엑셀·요청서에 없어 제가 제안하는 규칙 (승인 필요)

---

## 1. 업무 흐름

```
 거래처 주문 (전화·메일·온라인몰·아이마켓·베트남)
        │
        ▼
 ① 접수 ──▶ ② 발주확정 ──▶ ③ 제작중/입고대기 ──▶ ④ 납품준비 ──▶ ⑤ 부분납품 ──▶ ⑥ 납품완료
   │            │                │                      │              │  ▲
   │            │                │                      │              └──┘ (2차·3차 납품)
   └────────────┴──────┬─────────┴──────────────────────┘
                       ▼
                ⑦ 보류  ⇄  (재개 시 이전 상태로)
                ⑧ 취소  (전체 취소 또는 잔량 '마감')

 반품/정정: 납품완료·부분납품 품목에 '반품' 또는 '이력 무효화' 행을 추가 → 미납수량 재계산
```

| 단계 | 엑셀에서 하던 방식 [엑셀] | 시스템 |
|---|---|---|
| 접수 | 시트에 행 추가 | [신규 발주 등록] 또는 엑셀 일상 업로드 |
| 제작·매입 지시 | '일정/진행상황'에 `경성기공`, `하루일정으로 만들어주세요` | 품목별 `제작/매입처`, `진행 메모`, 상태 ③ |
| 재고 확인 | `재고 보유`, `재고없음`, `현재고 0` | 진행 메모 (2차: 재고 연계) |
| 출고 | 발송날짜 입력 + 행 노란색 | **납품 등록** (날짜·수량·담당자) |
| 부분출고 | 비고에 `1/19 30개 발송 / 1/23 48개` | 납품이력 여러 행, 미납 자동계산 |
| 잔량 종결 | 셀 메모 `미납 수량 마감처리`, `8개로 마감` | **잔량 마감** (= 마감수량 기록, 사유 필수) |
| 반품 | 수량 -40 행 추가 | **반품 등록** (RETURN 이력) |
| 취소 | 취소선, `재고없음으로 발주취소` | 상태 ⑧ + 사유 |

### 1-1. 상태 자동 판정 규칙 [제안]

품목 상태는 사람이 바꾸는 상태(①②③④⑦⑧)와 **수량으로 자동 결정되는 상태(⑤⑥)** 로 나눕니다.

| 조건 (품목 단위) | 표시 상태 |
|---|---|
| 상태 = 취소 | ⑧ 취소 |
| 상태 = 보류 | ⑦ 보류 |
| 유효납품 > 0 이고 미납 > 0 | ⑤ 부분납품 |
| 미납 = 0 이고 (유효납품 > 0 또는 마감수량 > 0) | ⑥ 납품완료 |
| 그 외 | 사람이 지정한 ①~④ |

발주(헤더) 상태 = 품목 상태 요약 [제안]: 취소 제외한 품목이 모두 완료 → 완료 / 하나라도 납품 있음 → 부분납품 / 그 외 → 가장 앞 단계 품목의 상태.

### 1-2. 날짜 표시 규칙 [제안]

| 표시 | 조건 |
|---|---|
| 🔴 납기 지연 | 납기일 < 오늘 AND 미납 > 0 AND 상태가 취소·보류가 아님 |
| 🟠 납기 임박 | 오늘 ≤ 납기일 ≤ 오늘+3일 (기준일수는 설정에서 변경) AND 미납 > 0 |
| 납기 없음 | 납기일 공란 → 지연 판정 안 함 (엑셀에는 납기 칸이 없으므로 이관분은 대부분 해당) |

### S5. 엑셀 업로드 마법사 (8단계)

```
 ①파일 선택 ─ ②시트 선택 ─ ③컬럼 매핑 ─ ④미리보기 ─ ⑤오류·중복·누락 ─ ⑥신규/갱신 선택 ─ ⑦최종 확인 ─ ⑧결과
```

| 단계 | 내용 |
|---|---|
| ① | 파일 끌어놓기. 모드 선택: **일상 등록**(기본) / **최초 데이터 이관**(관리자만). 같은 파일(해시) 재업로드 시 경고 |
| ② | 시트 목록 + 행 수, 시트별 발주구분·사업부 지정. '외화 단가 계산'·'업체 정보'는 기본 제외 (업체 정보는 거래처 가져오기로 분리) |
| ③ | 헤더 동의어 사전으로 자동 매핑 (예: `바코드 넘버`=`바코드 번호`=barcode), 드롭다운으로 수동 수정, 시트별 기본 담당자 지정 |
| ④ | 변환 결과 표 (원본값 ↔ 변환값 나란히), 서식 규칙 토글 (노란색=완료, 취소선=취소) |
| ⑤ | 탭: 오류(저장 불가) / 경고(저장 가능) / 중복 / 신규 거래처 후보 / 부분납품 후보. **오류 행 엑셀 다운로드** |
| ⑥ | 중복 행 처리: 건너뛰기 / 기존 갱신 (납품이력은 절대 덮어쓰지 않음) / 신규로 등록 |
| ⑦ | "신규 1,203 · 갱신 0 · 건너뜀 5 · 오류 12" 요약 후 저장 |
| ⑧ | 결과 + 업로드 이력 번호. 실패 시 **전체 롤백** (한 트랜잭션) |

**최초 이관 vs 일상 등록 차이** [확정 요구 → 세부는 제안]

| | 최초 데이터 이관 | 일상 엑셀 등록 |
|---|---|---|
| 권한 | 관리자 | 일반 직원 이상 |
| 대상 | 2026 발주내역서 전체 | 새로 받은 발주 엑셀 몇 행 |
| 발주번호 | `L-시트-행번호` 계열 | 일반 발주번호 자동 생성 |
| 원본 행 보존 | legacy_rows 에 전부 | 업로드 파일·행 지문만 |
| 서식(노란색·취소선) 해석 | 옵션 제공 | 사용 안 함 |
| 묶음(한 발주) | 추천만, 기본 1행=1발주 | 같은 거래처·날짜는 한 발주로 묶기 기본 [제안] |
| 실행 | 테스트 DB 리허설 후 운영 반영 | 바로 반영 |

### S6. 거래처 관리

```
┌ 거래처 [🔍      ] [구분▾]  [+ 거래처 추가]  [중복 의심 3건]  ┐
│ 거래처명 │구분 │배송방법 │화물지점 │연락처 │진행 발주│미납 │  ← 클릭 시 발주내역 탭 │
```
- 등록 시 정규화 이름(공백·(주)·주식회사 제거) 비교로 **중복 경고**, '별칭'으로 합치기 (예: `MRO 재고` → `MRO재고`).

### S7. 설정 (관리자)
- 사용자: 이름, 별칭(엑셀 표기), 역할, 허용 사업부, 사용/중지
- 상태값: 이름·색·아이콘·순서 변경, 사용 중지 (코드값은 고정 — 집계 규칙이 코드 기준이라서)
- 사업부·발주구분, 납기 임박 기준일(기본 3일), 발주번호 규칙

## 5. 색약 대응 상태 표시 [확정 요구]

색만으로 구분하지 않고 **아이콘 + 글자 + 테두리 모양**을 같이 씁니다. 색은 채도를 낮춘 배경색.

| 상태 | 아이콘 | 라벨 | 색 (배경) |
|---|:-:|---|---|
| 접수 | ○ | 접수 | 회색 |
| 발주확정 | ◉ | 발주확정 | 파랑 |
| 제작중/입고대기 | ⚙ | 제작·입고대기 | 보라 |
| 납품준비 | ▣ | 납품준비 | 청록 |
| 부분납품 | ◐ | 부분납품 | 주황 |
| 납품완료 | ✔ | 납품완료 | 초록 |
| 보류 | ‖ | 보류 | 노랑 (점선 테두리) |
| 취소 | ✕ | 취소 | 회색 + 취소선 |
| 납기 지연 | ⚠ | 지연 D+n | 빨강 굵은 테두리 |
| 납기 임박 | ⏰ | D-n | 주황 테두리 |

## 6. 배포 방식 비교

| 항목 | A. Supabase (관리형 Postgres) + Vercel | B. 사내 NAS (Synology 등) | C. 별도 서버 (VPS / 클라우드 VM) |
|---|---|---|---|
| 초기 비용 | 0원 (무료 플랜) | NAS 보유 시 0원 | 0원 |
| 월 비용 | 무료 플랜 가능 / **운영 권장 Pro 약 $25** (+ Vercel Pro $20 선택) | 전기료 | 약 1~3만원 |
| 백업 | 자동 일일 백업 (Pro), PITR 옵션 | 직접 구성 (Hyper Backup 등) | 직접 구성 (pg_dump + 외부 저장소) |
| 유지관리 | DB·OS 패치 불필요 | DSM·Docker·DB 직접 관리 | OS·DB·보안 패치 직접 |
| 외부(모바일) 접속 | 기본 지원 (HTTPS) | 포트포워딩·DDNS·인증서 필요, 보안 위험 | 지원 |
| 보안 | 관리형 + RLS | 사내망은 안전하나 외부 노출 시 위험 | 직접 책임 |
| 장애 대응 | 업체 책임 | 정전·디스크 고장 시 중단 | 직접 |
| 데이터 위치 | 해외/국내 리전 선택 (서울 리전 있음) | 사내 | 선택 |

**추천 [제안]**: **A. Supabase(서울 리전, Pro) + Vercel** — 백업·보안·외부 접속을 가장 적은 관리로 해결. 비용을 0으로 시작하려면 무료 플랜으로 시범 운영 후 전환.
- 사내 NAS는 **모델·DSM 버전·Docker 지원·백업 정책을 확인하기 전에는 설치하지 않습니다.** (요청서 지시) 대신 NAS는 **추가 백업 보관소**(일일 pg_dump 파일 복사)로 쓰는 것을 제안합니다.
- 운영 DB와 테스트 DB는 **별도 Supabase 프로젝트**로 분리.
