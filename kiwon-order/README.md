# KIWON 통합 발주관리 시스템 (1단계 시안)

기원툴스·기원MRO 사내 발주관리 웹 시스템입니다. 지금은 **승인 전 시안**입니다.
- 가상 테스트 데이터만 들어 있고, 입력한 내용은 **그 브라우저에만** 저장됩니다 (localStorage).
- 운영 서버 배포, 운영 DB 연결, 실제 데이터 이관은 **하지 않았습니다.**
- 원본 엑셀(`2026_기원 발주내역서.xlsx`)은 개인 구매자 정보가 있어 저장소에 올리지 않습니다 (`.gitignore` 에 `*.xlsx`).

## 실행

```bash
cd kiwon-order
npm install
npm run dev        # http://localhost:3000
npm test           # 단위 테스트 (계산 규칙·엑셀 정리 규칙·업로드 저장 묶음)
npm run lint       # 타입 검사
npm run build      # 운영 빌드 확인
```

상단 오른쪽 **시연용 로그인 전환**으로 관리자/일반 직원/조회 전용 화면을 바꿔 볼 수 있습니다.
`설정·이력 → 시안 데이터 초기화`로 처음 상태로 되돌립니다.

## 테스트 방법

1. **자동 테스트** `npm test`
   - 요청서 예시: 100개 중 30 + 40 납품 → 미납 30, 초과 납품 차단, 반품·정정 반영, 마감수량
   - 실제 엑셀에서 발견한 값: `26.06.10`, `2026년 6/9`, 일련번호 `46162`, `046-065`, `$ 7.10`, `무상샘플`, `교환`, `-40`, `HAI/KISHIN`, `아이마켓(진양오일씰)` 등
2. **실제 파일 검증 (로컬에서만)**
   `XLSX=/경로/2026_기원\ 발주내역서.xlsx npx vitest run src/lib/excel/real.local.test.ts`
   (이 테스트 파일은 저장소에 올리지 않습니다.) 브라우저에서도 같은 파일을 최초 이관 모드로 올려 확인했습니다.
   결과: 4,208행 → 4,202행 등록, 오류 6행은 원본으로만 보존 (음수 수량 1, 깨진 값 2, 수량이 날짜로 바뀐 칸 1, 내용이 거의 없는 행 1, 상품명 누락 1).
3. **화면 확인**
   - 대시보드 카드를 누르면 같은 조건의 목록으로 이동
   - 목록 행 클릭 → 상세 패널 → 납품 등록 (미납보다 많이 넣으면 막힘) → 정정 → 수정이력 탭 확인
   - 상세 패널의 `[시연] 다른 직원이 동시에 수정한 상황 만들기` → 변경 저장 → 충돌 안내 확인
   - 신규 등록: 거래처 입력 후 Enter, 품번 `KW100229` Enter → 상품정보 자동 입력, Ctrl+Enter 저장
   - 엑셀 업로드: 관리자로 전환 → 최초 데이터 이관 → 원본 파일 선택 → 8단계 진행

## 시안의 한계 (2단계 이후 구현)

- 로그인은 시연용 사용자 전환입니다. 실제 인증·서버 권한 검사는 DB 연결 단계에서 구현합니다 (규칙은 `store.tsx` 에 같은 이름으로 준비).
- 엑셀은 브라우저에서 읽습니다. 운영에서는 서버에서 읽고 원본 파일을 보관합니다.
- 메모 속 납품 기록(`1/19 30개 발송`)은 후보로 **표시만** 하고, 납품이력 자동 등록은 하지 않습니다 (확인 후 반영 방식 제안).
- 대용량 이관 후에는 브라우저 저장 용량(약 5MB)을 넘어 새로고침 시 일부가 사라질 수 있습니다. 시안 한정 문제입니다.
- `exceljs` 의존성(uuid)에 보통 등급 보안 권고가 있어, 운영 전 라이브러리를 다시 검토합니다.
